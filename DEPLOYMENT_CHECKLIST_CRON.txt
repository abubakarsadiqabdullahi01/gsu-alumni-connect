IF SOMETHING GOES WRONG
═════════════════════════════════════════════════════════════════════════════

Problem: Cron doesn't show in Vercel dashboard
Fix: 
  - Verify vercel.json is in project root: ls vercel.json
  - Redeploy: git push origin main
  - Wait 2 minutes and refresh dashboard

Problem: Job stays "Processing..." forever
Fix:
  - Check CRON_SECRET is set in Vercel
  - Check all env vars are set (DB_URL, REDIS_URL, etc.)
  - Check function logs for error messages
  - Test locally first: pnpm worker:import

Problem: Processing crashes with error
Fix:
  - View function logs (see VERIFY IN LOGS above)
  - Check for missing environment variables
  - Verify database connection works
  - Verify Redis connection works

Problem: "Unauthorized" error in logs
Fix:
  - Verify CRON_SECRET value in Vercel matches what's in code
  - Regenerate secret if needed
  - Redeploy after updating


WHAT HAPPENS AUTOMATICALLY NOW
═════════════════════════════════════════════════════════════════════════════

User uploads file:
  1. Job created in database
  2. Job enqueued to Redis/BullMQ
  3. Self-trigger fires immediately
  4. Processing starts (< 100ms)
  5. Status updates: QUEUED → RUNNING → COMPLETED
  6. Frontend sees update and shows "Completed!"

If self-trigger fails:
  1. Next cron minute fires (max 60 second wait)
  2. Picks up QUEUED job
  3. Processing starts
  4. Same result - no job is ever stuck

If job crashes midway:
  1. Next cron minute sees stalled job (heartbeat > 2 min old)
  2. Recovers and restarts
  3. Job completes successfully
